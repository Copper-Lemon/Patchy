# Right dock column

The right column holds Layers/Channels/Paths (tabbed), History, Properties, Info and Palette (`right_dock_stack_names` in `src/ui/main_window_docks.cpp`). Every dock in it shares one width.

## Width

- **Two widths.** `MainWindow::update_right_dock_minimum_width` measures the content-fit width `right_dock_minimum_width_`: the Layers panel layout minimum (the footer buttons, or the blend row at its wrapped width; see [layer-panel.md](layer-panel.md)) plus the dock chrome, never below `kRightDockMinimumWidth`. The chrome is the dock minus the Layers panel's scroll viewport, measured once the dock is laid out (on its first show, and lazily from `set_right_dock_stack_width`). The panel itself can be wider than the viewport, so never measure against the panel. Never add a competing hardcoded width.
- **Opening width.** Until the user or a script picks a width (`right_dock_width_follows_minimum_`), the column is pinned at the content-fit width and re-pinned whenever it changes (language switch, restyle). It therefore opens with no dead strip beside the Layers footer in every language (GitHub issue 96, `ui_right_dock_opens_at_content_width_without_gap`).
- **Picked widths.** The handle drag and `patchy.ui.setSidePanelWidth` go through `set_right_dock_stack_width`, which clamps to `kRightDockFloorWidth` (120) .. window width - 260 and keeps the result, narrower than the content included. The handle drag (`drag_right_dock_stack_width`) snaps to the content-fit width within `kRightDockSnapDistance` (10 px) of it and then follows that width again like the opening width (`ui_right_dock_drag_snaps_to_content_width`); the script call never snaps. `pin_right_dock_stack_width` fixes the width of the bottom docked dock only (the layout's, once shown) and leaves every other dock at the floor; one fixed dock pins the whole column. Qt draws no separator after a fixed-width dock in a vertical column (`QDockAreaLayoutItem::hasFixedSize`), so fixing every dock killed the dock-to-dock drags (`ui_right_dock_separator_drags_between_docks`) and a floated dock kept the fixed width (`ui_floating_right_dock_auto_expands`). Floating, re-docking, closing and reopening a dock re-run the pin (`reapply_right_dock_stack_width`, from `topLevelChanged` and the dock's Show/Hide events, never `visibilityChanged`, which fires during window destruction). `QMainWindow::resizeDocks` does not hold the column at an exact width; do not switch to it.
- **Overflow.** `install_collapsible_dock_title` puts each panel inside a `RightDockOverflowArea` (`rightDockOverflowScroll`). Properties is already its own `QScrollArea`, with the horizontal bar as needed. Below a panel's minimum width the panel keeps that width and scrolls sideways, with the bar at the bottom. The area never scrolls vertically: it hands the panel the viewport's full height, and its minimum height grows by the bar while it shows. It places the panel by hand because `widgetResizable` would size the height-for-width Layers panel to its preferred height and clip the footer. Dock title labels use an `Ignored` width policy, so a long title clips instead of holding the column wide (`ui_right_dock_drags_below_content_minimum_with_scroll`).
- **Handle.** Every docked dock hosts the 7px `rightDockResizeHandle` over its left edge (`install_right_dock_width_handle`), with a matching inset on title bars and contents (`ui_right_dock_contents_clear_width_handle`). It must stay usable while a non-modal preview dialog is open; the preview edit lock disables panel widgets, never the docks or the handle (`ui_right_dock_drag_works_during_preview_dialog`). Modal windows (Liquify, apply progress boxes) block it, as Qt blocks all main-window input.
- Tests that need the no-scroll width read `MainWindowTestAccess::right_dock_content_minimum_width`, not `dock->minimumWidth()` (the floor). Keep staged `setSidePanelWidth` values in tests above it unless the test is about scrolling.

## Heights, collapse and floating

Right-dock panel heights must never pin the window taller. A collapsed dock pins min == max to its title bar's styled sizeHint (`refresh_collapsed_right_dock_heights` re-pins after the stylesheet lands). Expanding sets a temporary minimum that `MainWindow::handle_right_dock_panel_toggled` releases one event-loop hop later, re-clamping the window to the screen only if the toggle grew it. Neither the Layers panel's 300 px floor nor an expand demand may hold the window's minimum above `available_window_height()`: `fit_right_dock_floors_to_screen` (the expanded dock first, then Layers with its panel's 240 px and list's 120 px floors, then the column; never below a layout's own minimum) lowers them until the window fits, from the startup clamp and from every expand, so a short screen or a large interface scale never leaves the default column off-screen and an expand grows the window only past the content minimums (GitHub issue 108, `ui_right_dock_floors_fit_the_screen_height`; the Wayland side is in [wayland.md](wayland.md)). Panels that can outgrow their share scroll internally; never give a right-dock panel an unbounded minimum height (`ui_right_dock_panels_expand_within_window_height`, `ui_collapsed_right_docks_have_uniform_title_height`). A tab group (Layers, Channels, Paths) collapses and expands as one, because the group keeps its tallest member's height: a toggle sets every docked tabified sibling, and a dock docked into a group takes the group's state (GitHub issue 101, `ui_tabbed_right_dock_group_collapses_as_one`). `create_docks` sets `QMainWindow::GroupedDragging` (`ui_tabbed_right_dock_drags_out_by_tab`), but `handle_right_dock_title_drag_event` detaches only the dock under the cursor from a tabbed right dock (`ui_tabbed_dock_title_drag_floats_single_dock`): Qt's floating group window breaks with custom title bars. A floating group or single floating right dock (`floatingChrome` property) gets chrome from `handle_dock_group_window_event`: a divider-chrome strip with edge-resize cursors and blank areas that drag the window (`ui_dock_group_window_drags_by_blank_chrome`). On Wayland (or with `PATCHY_FIXED_PANELS=1`) `create_docks` clears Floatable and Movable on every right dock: an app cannot place its own windows there, and a panel turned into a window mid-drag lost the button release, leaving Qt holding the mouse (GitHub issue 102, `ui_right_docks_stay_in_column_where_windows_cannot_be_placed`). Floating docks skip the width pin and the handle, get a size nudge on toggle (`resync_native_frame_geometry`), and are always expanded: pulling a panel out auto-expands it and the collapse toggle shows only while docked (`ui_floating_right_dock_auto_expands`).
